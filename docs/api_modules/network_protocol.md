# 6. Network Protocol & Worker Threads

The server exposes a custom TCP binary protocol using **MsgPack** for structural metadata and raw byte streams for large hardware sample arrays.


## Protocol Components

### `FIREQNetworkPacket`
Dataclass encapsulating a network packet.
* **`header`** (*dict*): Metadata dictionary.
* **`data`** (*bytes | None*): Optional raw binary payload.
* **`to_buffers()`**: Serializes the packet into a tuple of byte buffers `(length_bytes, header_bytes, data_bytes)` optimized for zero-copy transmission via `socket.sendmsg`.

### `ReceiveWorker`
A background thread (`Thread`) that listens on the client socket. It reads the 4-byte header length, unpacks the MsgPack dictionary, receives any trailing binary payload defined by the `"tsize"` key, and places the resulting `FIREQNetworkPacket` into the server's input queue (`queue_in`).

### `SendWorker`
A background thread (`Thread`) responsible for outgoing transmissions. It pops items from a thread-safe `MemoryBoundedQueue` (`queue_out`) and streams them directly over the TCP socket using `socket.sendmsg()`.

### `DMAPayload`
Data structure generated by `DMANode` after capturing hardware runs:
* **`source`** (*str*): Name of the originating acquisition node.
* **`shots`** (*int*): Number of hardware shots stored in the byte array.
* **`dtype`** (*str*): Data format identifier (e.g., `"complex64"`).
* **`data`** (*bytes*): Raw binary memory buffer read from the DMA.
