RUN SWEEP (Streaming Binary Protocol)
======================================

Executes a multi-point parameter sweep with optimized "fast path" execution.
The server streams a single header followed by binary data frames for each
sweep point.


CLIENT REQUEST
--------------
{
  "cmd": "run_sweep",
  "session_id": "session_001",
  "sweep_id": "example_sweep_001",

  // Base configuration: same structure as run_experiment
  // Use "$VAR_NAME" placeholders for sweepable parameters
  "system": {
    "acquisition_0" : {
      $duration
      $output_type
      $rfrequency
      $rphase
      $rchannel
      $tof
    }

    "trigger_generator_0" : {
      $experiment_duration : 1000
      delay: {
        _name: "rtrig1"
        _channel: 1
        $delay: 123
      }
      delay: {
        _name: "dtrig1"
        _channel: 1
        _index: 1
        _generate_trigger: true/false
        $delay: 234
      }
    }


    "generator_0" : {

    }
      
  },

  // Sweep axes: server computes linspace(start, stop, num) in hardware units
  "variables": [
    { "name": "DRV_FREQ",  "start": 100.0, "stop": 120.0, "num": 5, "space": "lin" },
    { "name": "DRV_PHASE", "start": 0.0,   "stop": 3.14159, "num": 5, "space": "lin" },
    { "name": "RO_FREQ",   "start": 220.0, "stop": 260.0, "num": 5, "space": "lin" },
    { "name": "RO_PHASE",  "start": 0.0,   "stop": 3.14159, "num": 5, "space": "lin" },
    { "name": "RO_DUR",    "start": 800,   "stop": 1600,  "num": 5, "space": "lin" },
    { "name": "RO_GAIN",   "start": 0.1,   "stop": 0.9,   "num": 5, "space": "lin" },
    { "name": "ACQ_DUR",   "start": 1024,  "stop": 4096,  "num": 5, "space": "lin" },
    { "name": "D0",        "start": 10,    "stop": 200,   "num": 5, "space": "lin" },
    { "name": "D1",        "start": 10,    "stop": 200,   "num": 5, "space": "lin" },
    { "name": "D2",        "start": 0,     "stop": 50,    "num": 5, "space": "lin" },
    { "name": "RO_DLY",    "start": 300,   "stop": 1200,  "num": 5, "space": "lin" },
    { "name": "SHOT_CC",   "start": 2000,  "stop": 8000,  "num": 5, "space": "lin" },
    { "name": "SHOTS",     "start": 32,    "stop": 256,   "num": 5, "space": "lin" }
  ],

  "sweep_mode": "cartesian"             // "cartesian" or "zipped"
}


SERVER RESPONSE - STREAMING PROTOCOL
------------------------------------

1. SWEEP HEADER (sent once at the beginning)
{
  "type": "sweep_header",
  "cmd": "run_sweep",
  "session_id": "session_001",
  "sweep_id": "example_sweep_001",
  "stream_mode": "header_binary",
  "n_points": 125,                      // Total sweep points (product of all variable nums)
  "adc_metadata": {
    "0": {
      "dtype": "iq_int16",              // "iq_int16" for decimated/raw, "iq_int32" for accumulated
      "shape": [32, 1024]               // [shots, samples] or [samples] if decimated
    }
  },
  "chunks_per_point": 1                 // Number of binary frames per sweep point
}


2. BINARY STREAM (repeated for each sweep point)
For each point in the sweep:
  For each ADC:
    [4 bytes: ADC index (uint32 big-endian)]
    [4 bytes: data length in bytes (uint32 big-endian)]
    [N bytes: compact I/Q structured array via .tobytes()]

  Timing trailer (after all ADC frames for this point):
    [4 bytes: FPGA active time in ms (float32 big-endian)]
    [4 bytes: SW overhead time in ms (float32 big-endian)]

Example with 2 points, 1 ADC each (iq_int16 format):
  Point 0: [adc_idx=0][length=65536][65536 bytes][hw_ms][sw_ms]
  Point 1: [adc_idx=0][length=65536][65536 bytes][hw_ms][sw_ms]
  (4x smaller than complex128 format)


3. SWEEP STATUS (sent after all points complete)
{
  "type": "sweep_status",
  "cmd": "run_sweep",
  "session_id": "session_001",
  "sweep_id": "example_sweep_001",
  "ok": true,
  "n_points": 125,
  "n_completed": 125,
  "debug_timing": {
    "total_server_time_ms": 5234.2
  },
  "error": null
}


SWEEP MODES
-----------
- "cartesian": Full grid of all variable combinations
  Total points = product of all variable nums (e.g., 5^13 = 1,220,703,125)

- "zipped": Variables swept together (all must have same num)
  Total points = num (e.g., 5)


VARIABLE SPECIFICATION
----------------------
Each variable can be defined as:
  { "name": "VAR", "start": 0.0, "stop": 10.0, "num": 11, "space": "lin" }

Or with explicit values:
  { "name": "VAR", "values": [0.0, 2.5, 5.0, 7.5, 10.0] }

space options:
  - "lin": Linear spacing (default)
  - "log": Logarithmic spacing


CLIENT USAGE PATTERN
--------------------
# Compact dtype mapping
COMPACT_DTYPES = {
    "iq_int16": np.dtype([("i", "<i2"), ("q", "<i2")]),  # 4 bytes/sample
    "iq_int32": np.dtype([("i", "<i4"), ("q", "<i4")]),  # 8 bytes/sample
}

def resolve_dtype(dtype_str):
    return COMPACT_DTYPES.get(dtype_str, np.dtype(dtype_str))

def to_complex(arr, dtype_str):
    if dtype_str in COMPACT_DTYPES:
        return arr["i"].astype(np.float64) + 1j * arr["q"].astype(np.float64)
    return arr

header = receive_json_message()
assert header["type"] == "sweep_header"
n_points = header["n_points"]
adc_meta = header["adc_metadata"]
chunks_per_point = header.get("chunks_per_point", 1)

for point_idx in range(n_points):
    for chunk_idx in range(chunks_per_point):
        for adc_idx_str, meta in adc_meta.items():
            # Receive binary frame
            frame_header = recv_exact(8)
            adc_idx, data_len = struct.unpack(">II", frame_header)
            data_bytes = recv_exact(data_len)

            # Parse with compact dtype
            dtype = resolve_dtype(meta["dtype"])
            arr = np.frombuffer(data_bytes, dtype=dtype)
            arr = arr.reshape(meta["shape"])

            # Convert to complex128 for analysis
            complex_arr = to_complex(arr, meta["dtype"])

    # Receive timing trailer
    timing_bytes = recv_exact(8)
    hw_ms, sw_ms = struct.unpack(">ff", timing_bytes)

status = receive_json_message()
assert status["type"] == "sweep_status"


ABORT COMMAND
-------------
To abort a running sweep, send:
{
  "cmd": "abort",
  "session_id": "session_001"
}

Server responds immediately:
{
  "ok": true,
  "cmd": "abort",
  "session_id": "session_001",
  "message": "Sweep aborted"
}

The sweep_status will show n_completed < n_points.


NOTES
-----
- Variable placeholders use "$NAME" syntax in the base config
- Only numeric parameters can be swept (frequencies, phases, delays, etc.)
- Channel assignments (trigger routing) cannot be swept
- The server uses a "fast path" optimization to minimize reconfiguration
- Client should compute sweep points locally from variables for correlation


COMPACT I/Q FORMAT (Protocol 0.2)
---------------------------------
Server transmits acquisition data in compact structured arrays for bandwidth efficiency:

  - decimated/raw modes: "iq_int16" = [('i', '<i2'), ('q', '<i2')]
    4 bytes per sample (4x smaller than complex128)

  - accumulated mode: "iq_int32" = [('i', '<i4'), ('q', '<i4')]
    8 bytes per sample (2x smaller than complex128)

The compact format preserves the original FPGA hardware precision (int16 for
decimated/raw, int32 for accumulated). Client conversion to complex128 is
lossless since float64 can exactly represent all integer values in these ranges.
