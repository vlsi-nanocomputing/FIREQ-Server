RUN EXPERIMENT (Streaming Binary Protocol - Optimized)
======================================================

Executes a single experiment configuration and streams acquisition data back
to the client. Uses header_binary protocol: single header with chunk count,
followed by pure binary streams (matching the sweep protocol pattern).


CLIENT REQUEST
--------------
{
  "cmd": "run_experiment",
  "session_id": "ses_001",

  // Optional: inline definitions for JIT compilation
  "envelopes": { ... },
  "waves": { ... },

  "generators": [
    {
      "gen_index": 0,
      "drive": {
        "frequency_mhz": 150.0,
        "phase": 0.0,
        "channel": 1,                 // Trigger channel to listen on
        "nyquist_zone": 1,            // Optional (auto Mix-Mode)
        "fifo": ["pi_pulse_x", "vz_gate_pi_half", "pi_pulse_x"],
        "fifo_start_index": 1         // Hardware FIFO offset (default: 1)
      },

      "readout": {
        "frequency_mhz": 200.0,
        "phase": 0.0,
        "channel": 2,                 // Trigger channel to listen on
        "wave": {                     // Explicit readout wave definition
          "envelope": "RECT_READOUT",
          "duration": 1024,
          "gain": 0.5
        }
      }
    }
  ],

  "acquisitions": [
    {
      "acq_index": 0,
      "frequency_mhz": 200.0,
      "phase": 0.0,
      "channel": 2,                   // Trigger channel to listen on
      "duration": 2048,               // Acquisition window duration (samples)
      "tof": 150,                     // Time of Flight delay (samples)
      "output_type": "decimated"      // "raw", "decimated", or "accumulated"
    }
  ],

  "trigger": {
    "shots": 1000,                    // Number of hardware repetitions
    "shot_duration": 5000,            // Total shot duration in clock cycles
    "drive_start_index": 1,
    "drive": {
      "1": {                          // Physical trigger channel (string key)
        "delay": [
          [10, 1],                    // [delay_cycles, generate_flag]: trigger after 10 cycles
          [200, 0]                    // [delay_cycles, generate_flag]: delay only (no trigger)
        ]
      }
    },
    "readout": {
      "2": {                          // Trigger channel (string key)
        "delay": 500                  // Delay before readout trigger (cycles)
      }
    }
  },

  "timeout": 10.0                     // Optional: acquisition timeout in seconds
}


SERVER RESPONSE - STREAMING PROTOCOL
------------------------------------

The server streams three types of messages in sequence:

1. EXPERIMENT HEADER (sent once at the beginning)
{
  "type": "experiment_header",
  "cmd": "run_experiment",
  "session_id": "ses_001",
  "ok": true,
  "config_log": ["gen 0 drive frequency: 150.0 MHz", "..."],
  "adc_metadata": {
    "0": {                            // ADC index (string key)
      "dtype": "iq_int16",            // "iq_int16" for decimated/raw, "iq_int32" for accumulated
      "shape": [2048]                 // Shape depends on output_type
    }
  },
  "n_chunks": 3,                      // Total binary chunks to expect
  "stream_mode": "header_binary",     // Protocol mode identifier
  "error": null
}

2. BINARY CHUNKS (repeated n_chunks times)
For each chunk:
  For each ADC:
    [4 bytes: ADC index (uint32 big-endian)]
    [4 bytes: data length in bytes (uint32 big-endian)]
    [N bytes: compact I/Q structured array via .tobytes()]

  Timing trailer (after all ADC frames for this chunk):
    [4 bytes: FPGA active time in ms (float32 big-endian)]
    [4 bytes: SW overhead time in ms (float32 big-endian)]

3. TIMING (sent last)
{
  "type": "experiment_timing",
  "cmd": "run_experiment",
  "session_id": "ses_001",
  "metadata": {
    "debug_timing": {
      "total_server_time_ms": 150.5,
      "fpga_active_ms": 45.2,
      "sw_overhead_ms": 8.3,
      "server_encode_ms": 12.3,
      "payload_bytes": 16384000
    }
  }
}


OUTPUT TYPES
------------
- "raw": Full waveform data, shape [shots, samples * parallelism]
- "decimated": Averaged across shots, shape [samples]
- "accumulated": Single complex value per shot, shape [shots]


CLIENT USAGE PATTERN
--------------------
header = receive_json_message()
assert header["type"] == "experiment_header"
n_chunks = header["n_chunks"]
adc_meta = header["adc_metadata"]

for chunk_idx in range(n_chunks):
    for adc_idx_str, meta in adc_meta.items():
        # Receive binary frame
        frame_header = recv_exact(8)
        adc_idx, data_len = struct.unpack(">II", frame_header)
        data_bytes = recv_exact(data_len)
        arr = np.frombuffer(data_bytes, dtype=meta["dtype"])
        # Note: per-chunk shape may differ from full experiment shape
        # when shots are split across chunks

    # Receive timing trailer
    timing_bytes = recv_exact(8)
    hw_ms, sw_ms = struct.unpack(">ff", timing_bytes)

timing = receive_json_message()
assert timing["type"] == "experiment_timing"


BINARY DATA RECONSTRUCTION
--------------------------
Client-side reconstruction for each ADC (compact I/Q format):

  # Resolve dtype from metadata
  COMPACT_DTYPES = {
      "iq_int16": np.dtype([("i", "<i2"), ("q", "<i2")]),  # decimated/raw: 4 bytes/sample
      "iq_int32": np.dtype([("i", "<i4"), ("q", "<i4")]),  # accumulated: 8 bytes/sample
  }
  dtype = COMPACT_DTYPES.get(meta["dtype"], np.dtype(meta["dtype"]))

  # Parse structured array
  arr = np.frombuffer(data_bytes, dtype=dtype)
  arr = arr.reshape(shape)  // shape from metadata

  # Convert to complex128 for analysis
  complex_arr = arr["i"].astype(np.float64) + 1j * arr["q"].astype(np.float64)

Result is a complex numpy array where:
  - Real part = I component (from int16 or int32)
  - Imaginary part = Q component (from int16 or int32)
  - Use np.real(arr), np.imag(arr), or np.abs(arr) for amplitude

Note: The compact format reduces bandwidth by 4x for decimated/raw modes
(4 bytes/sample vs 16 bytes/sample for complex128). The conversion to
complex128 is lossless since float64 can exactly represent all int16/int32 values.


NOTES
-----
- channel: 0 disables the trigger/acquisition for that block
- Envelopes/waves can be defined inline or pre-uploaded
- Multiple ADCs can be acquired simultaneously
- Chunks are split based on hardware buffer limits (max_hw_shots)
- n_chunks in header tells client exactly how many binary frames to expect
- Protocol matches sweep format for consistency
